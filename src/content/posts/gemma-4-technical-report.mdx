## 一句话结论

**Gemma 4 是覆盖 2.3B effective、4.5B effective、12B、26B-A4B MoE 与 31B 的开放权重多模态家族：用 4:1/5:1 local-global attention、p-RoPE、global K=V 与 KV sharing 控制长上下文，用 QAT 和小型 autoregressive MTP drafter 降低内存与解码成本，并在 12B 上直接把 raw image patch / 40ms audio chunk 投影进 LLM，移除独立 encoder。官方结果显示它相对 Gemma 3/3n 跨文本、视觉、音频和 128k context 都有显著提升，但报告没有给训练 token、thinking budget 与关键设计的同预算消融，不能把所有提升归因给任一模块。**

## 模型矩阵：先把名字和参数口径说清楚

| 模型 | 主干类型 | 报告参数口径 | Vision | Audio | MTP drafter |
| --- | --- | ---: | ---: | ---: | ---: |
| E2B | Dense + per-layer embeddings | 2.3B effective（总约 5B） | 150M | 305M | 76M |
| E4B | Dense + per-layer embeddings | 4.5B effective（总约 8B） | 150M | 305M | 77M |
| 12B | Dense, encoder-free | 12B | 无独立 encoder | 无独立 encoder | 400M |
| 26B-A4B | MoE | 26B total / 3.8B active | 550M | 未列独立 audio | 430M |
| 31B | Dense | 31B | 550M | 未列独立 audio | 500M |

全家族词表为 262k，采用 Gemini 系列相同的 SentencePiece tokenizer：拆分数字、保留 whitespace、提供 byte-level fallback。报告把 26B-A4B 名字四舍五入为 A4B；Table 1 的精确 activated einsum 参数约 2.8B，加 embedder/其他模块后报告总 active 约 3.8B。比较模型大小时必须看同一列，不能把 effective、active 与 total 混用。

## Decoder 主干：local/global attention 的内存算盘

Gemma 4 仍是 decoder-only Transformer，使用 pre-norm + post-norm RMSNorm，并在 query/key 上使用 QKNorm。E2B 的 attention block ratio 是 4 个 local 配 1 个 global，其余模型为 5:1。

标准 causal attention 可写为

$$
\operatorname{Attn}(Q,K,V)
=\operatorname{softmax}\!\left(
\frac{QK^\top}{\sqrt{d_k}}+M
\right)V,
$$

global layer 的 $M$ 只遮未来，local layer 还把窗口外历史遮掉。若 context 长度为 $L$、local window 为 $w\ll L$，单层 attention interaction 从 $O(L^2)$ 降到 $O(Lw)$；但周期性 global layer 仍提供全局信息通道。

报告在 global attention 使用 $p$-RoPE，$p=0.25$，local attention 使用普通 RoPE；global/local RoPE frequency 分别设置为 1M / 10k。除 E2B/E4B 外，global layer 令 values = keys，即 $V=K$，省去一份独立 global value cache。结合 local/global 比例与 KV sharing，报告称 global KV footprint 最多减少 37.5%。

E2B/E4B 另使用 20/35 与 18/42 的 KV cache sharing ratio。报告没有把每一项单独做同预算 latency/quality 消融，所以“37.5%”是缓存结构上限，不是端到端显存一定下降 37.5%。

## Vision：可变比例、轴向 2D-RoPE 与 token pooling

E2B/E4B 用 150M ViT，26B-A4B/31B 用 550M ViT，patch size 16；encoder 在 LLM 预训练时保持冻结。视觉位置同时包含：

- non-causal axial 2D-RoPE；
- 2D absolute positional embeddings；
- aspect-ratio preserving resize。

最大 vision token 数 $N_{\max}\in\{70,140,280,560,1120\}$。附录算法先在保持长宽比下选择 patch grid，再把 vision encoder 输出做 $3\times3$ pooling，减少交给 LLM 的 soft tokens。论文以 1120 tokens 报主视觉表，另给 280-token 结果；因此视觉 benchmark 数字包含高分辨率计算，不能和只用固定低分辨率的模型只按参数量比较。

## Audio：更小的冻结 encoder 与连续表示

E2B/E4B 的 305M audio encoder 接收 16kHz 音频，每 40ms 形成输入 chunk，包含两层 downsampling convolution 与 12 层 Conformer。相比 Gemma 3n 的 680M encoder，参数减少 55%。

它不做 vector quantization；LLM 直接接收连续 encoder representation。QAT 后 audio encoder on-disk footprint 从 390MB 降到 87MB，减少 78%。这解释的是 encoder 文件大小，不是整个 E2B/E4B 模型大小。

## 12B Encoder-Free：把“前端模型”压成 projection

12B 从头按统一架构训练，不挂独立 vision/audio encoder。

图像被切成 $48\times48\times3$ RGB patches，经一个约 35M 参数的大矩阵投影到 LLM embedding space；在 LayerNorm 前加入基于 2D coordinate 的 positional embedding。可以写成

$$
h_{i,j}^{\mathrm{img}}
=\operatorname{LN}\!\left(W_{\mathrm{img}}x_{i,j}+p_{i,j}^{2D}\right).
$$

音频在 16kHz 下按 40ms 切成 640 维原始向量，直接投影：

$$
h_t^{\mathrm{aud}}=W_{\mathrm{aud}}x_t+b_{\mathrm{aud}}.
$$

时间顺序由 decoder sequence position 表达，因此报告不再加单独 audio position。这个设计降低组件碎片与独立 encoder 内存，却把感知表示学习压力转移到大 LLM 主干和预训练数据上。报告给出 12B 的 ASR/S2TT 结果，证明路线可行，但没有与“同样 12B + 冻结 encoder”的严格 ablation，不能断言 encoder-free 一定质量更高。

## 预训练：报告写了基础设施，却留了最关键的 token 空白

数据覆盖 web documents、code、images 与 audio（audio 仅 E2B/E4B/12B），cutoff 为 2025 年 1 月。作者说明做 benchmark decontamination、recitation 风险、unsafe utterance 与隐私过滤。

但报告没有披露：

- 总训练 token / image / audio hours；
- 各语言、领域与模态比例；
- 数据来源清单、去重率或合成数据比例；
- 每模型训练 FLOPs、训练 step 或 energy。

因此无法做 Chinchilla-style data efficiency 分析，也无法把跨代增益分解为“更多数据”还是“更好架构”。

训练基础设施则相对具体：

| 模型 | TPU | Chips | Data shards | Sequence shards | Replicas |
| --- | --- | ---: | ---: | ---: | ---: |
| E2B | v6e | 4,096 | 16 | 8 | 32 |
| E4B | v6e | 6,144 | 16 | 16 | 24 |
| 12B | v4 | 12,288 | 16 | 16 | 48 |
| 26B-A4B | v6e | 6,144 | 16 | 16 | 24 |
| 31B | v6e | 10,240 | 16 | 16 | 40 |

optimizer state 用 ZeRO-3 式 sharding；多 pod replica reduction 走 datacenter network；软件栈为 JAX/Pathways、GSPMD 与 MegaScale XLA。大模型启用 slice-granularity elasticity，局部 TPU slice 故障时用较少 slice 继续训练，把中断延迟从分钟降到秒级。报告没有给实际故障率或吞吐提升，因此这是机制说明，不是量化可靠性结果。

## QAT：权重内存与 KV cache 必须分开算

报告提供 raw 与 quantized checkpoint：

- mobile quantization：per-channel 权重混合 int2/int4，activation int8；
- Q4_0：常见 blockwise 4-bit 权重量化；
- 为 fp16 稳定推理，在每个 block 加 scalar scale 约束 activation range。

以 text-only、32k context、int8 KV cache 为例：

| 模型 | bf16 权重 | quantized 权重 | 32k KV 额外 |
| --- | ---: | ---: | ---: |
| E2B | 4.6GB | 0.8GB | 0.05GB |
| E4B | 9.0GB | 2.3GB | 0.14GB |
| 12B | 24.0GB | 7.65GB | 0.28GB |
| 26B-A4B | 52.0/7.6GB total/active | 16.2/2.8GB | 0.28GB |
| 31B | 64.0GB | 19.2GB | 1.10GB |

这张表不能直接当峰值显存：没有 activation、runtime workspace、multimodal encoder 与 batch 并发。MoE 的 total/active 权重也不等于只需加载 active 权重；路由到不同 experts 通常仍要存储整个 expert pool。

## MTP Drafter：为 speculative decoding 单独训练一个小模型

每个模型附带 autoregressive multi-token prediction drafter。它读取主模型上一步 last-layer activation、token embedding 与主模型 KV cache，通过 4-layer Transformer 顺序预测未来 token。E2B/E4B drafter hidden size 256，26B-A4B/31B 为 1024，结构为 3 local + 1 global attention layer。

若 drafter 给 proposal $\tilde y_{t:t+k}$，主模型一次并行验证；被接受的公共前缀长度决定加速。报告没有给统一 acceptance rate、tokens/s 或端到端 speedup 表，所以只能确认它提供了 speculative decoding 组件，不能从“有 MTP”推断某个固定加速倍数。

E2B/E4B 为降低投影 262k vocabulary 的成本，先对 4,096 个 token cluster 做 top-$k$，把最终矩阵乘从

$$
d\times262{,}000
$$

缩到

$$
d\times4{,}096.
$$

报告称 acceptance rate 近似保持，但未列完整曲线。

## Instruction tuning 与 thinking mode

PT 模型经过类似 Gemma 3 的 post-training 变为 IT 模型，并新增 thinking mode：先输出 reasoning trace，再输出回答。报告说明过滤包含 PII、unsafe/toxic output、错误 self-identification 与 duplicate 的样本，并加入 attribution、hedging 与 refusal 数据以降低 hallucination。

PT/IT 共用 tokenizer，但 end token 不同：PT 输出 `<eos>`，IT 输出 `<turn|>`；IT 格式另含 function-calling control tokens。微调或 serving 若混用终止 token，会影响 generation termination，属于模型档案中最容易被忽略的工程细节。

报告没有披露 SFT/RL 数据量、偏好优化算法、reward/verifier 细节，也没有给 thinking token 上限。因此 Table 5 的模型比较应理解为“各自官方 thinking 配置的最终系统”，不是同 reasoning budget 的裸模型能力比较。

## 文本与 Agent 结果：强，但预算并不统一

<figure><img src="/paper-radar/images/gemma-4/results.svg" alt="Gemma 4 31B 相对 Gemma 3 27B 的代表性结果，以及量化内存和音频结果" width="1600" height="900" loading="lazy"/><figcaption>图 2：依据论文 Tables 3–9 重绘。不同表的 inference setting 不同：主静态 benchmark 多数开启 thinking，长上下文 Table 9 明确关闭 thinking。</figcaption></figure>

Gemma 4 31B 对 Gemma 3 27B 的报告结果包括：

- MMLU Pro：85.2 vs 67.6；
- AIME 2026：89.2 vs 20.8；
- LiveCodeBench v6 no-tools：80.0 vs 29.1；
- GPQA Diamond：84.3 vs 42.4；
- IFBench：76.0 vs 32.0；
- Terminal Bench Hard：36.0 vs 4.0；
- Tau2 retail：86.4 vs 6.6。

这些跨代差距很大，但 Gemma 3 27B 是 non-thinking，而 Gemma 4 表中默认 thinking；因此差距混合了模型、训练数据、post-training 与 test-time compute。它能证明最终产品代际提升，不能单独证明架构 sample efficiency。

Arena Text 截至 2026-06-19，Gemma 4 31B 为 1451±8，26B-A4B 为 1438±8；报告称 31B 是当时 dense open model 中最高，并与参数更大的 MoE open models 接近。Arena 是 blind pairwise human evaluation，但模型可能有不同 system prompt、sampling 与思考长度；Elo 也随参赛池和时间变化，不是永久绝对标尺。

## 视觉、音频与长上下文

视觉在最大 1120 vision tokens + thinking 下，31B/26B-A4B/12B/E4B/E2B：

- MMMU Pro：76.9 / 73.8 / 69.1 / 52.6 / 44.2；Gemma 3 27B 为 49.7；
- MATH-Vision：85.6 / 82.4 / 79.7 / 59.5 / 52.4；Gemma 3 为 46.0；
- OmniDocBench（越低越好）：0.131 / 0.149 / 0.164 / 0.181 / 0.290；Gemma 3 为 0.365。

音频方面，E4B 的 CoVoST 平均 CorpusBLEU 38.2，对应 Gemma 3n E4B 为 34.7；FLEURS 平均 WER/CER 0.075 对 0.085。E2B 分别为 35.4 对 31.6、0.090 对 0.108。报告把提升写为 translation 相对 +10%/+12%、transcription 相对 +12%/+17%，并同时将 encoder footprint 降 78%。

长上下文 Table 9 明确是 **without thinking**：

- RULER 128k：31B 96.4，26B-A4B 89.8，12B 91.2，E4B 86.6，E2B 70.4，Gemma 3 27B 66.0；
- LOFT retrieval 128k：79.5 / 66.3 / 66.4 / 58.5 / 50.5，对 Gemma 3 的 8.6；
- GraphWalks：31B 82.3，E2B 4.1，说明同一家族的小模型长上下文组合推理仍明显不足；
- MTOB full-book 约 256k 只报告 31B/26B-A4B/12B，E4B/E2B 为缺失，不应写成全家族支持同等 256k 能力。

## 安全与开放边界

报告称沿用 Gemini 级安全评测，覆盖 CSAM、dangerous content、sexual content、hate 与 harassment；训练前过滤 PII/敏感数据，post-training 做安全对齐，评测时不加外部 safety filter。作者声称相对 Gemma 3/3n 所有 content-safety category 改进且 unjustified refusal 保持低。

但报告没有给各类别 violation/refusal 的具体表、样本量、语言分层或置信区间。因此可以记录“官方报告的定性结论”，不能把它改写为可审计的安全率。开放权重也意味着 downstream fine-tune 可改变安全行为，系统部署仍需输入输出策略、权限隔离和业务评测。

Gemma 4 报告称 Apache 2.0 许可；具体 checkpoint 页面仍应核对其模型卡与访问条款。本文链接的是官方 31B IT repository，而不是把模型仓库误称为训练代码仓库。

## 与基线的真实比较

- **跨代基线**最完整：Gemma 3 27B / Gemma 3n 同团队、同家族，能说明最终系统代际进步；但 thinking setting 并不总一致。
- **开放模型横比**主要来自 Arena，公平性优于自报静态分数，但仍混合推理预算、prompt 与版本。
- **模型内规模曲线**覆盖 2B–31B 与 MoE，能看部署 trade-off；却没有同 training tokens/FLOPs 的 controlled scaling。
- **组件消融不足**：没有单独关掉 p-RoPE、K=V、KV sharing、encoder-free、QAT 或 thinking 的统一表。
- **推理效率证据分裂**：有权重/KV memory、encoder latency/size 和 MTP 结构，却没有全模型 tokens/s、TTFT、TPOT、batch 曲线。

## 局限与风险

- 训练数据规模与构成不透明，无法审计数据效率、版权、语言覆盖或 contamination 剩余风险。
- Thinking benchmark 未统一 token budget；高分可能伴随不可见的额外延迟与成本。
- 12B encoder-free 只有最终结果，没有严格同预算 encoder ablation。
- safety 部分缺数值；“rigorous”不能替代可复现评测表。
- 截止日期、模型版本与 Arena 参赛池都会变化，档案应记录而非抹去时间点。

## 工程启示

- 选 checkpoint 时先按部署约束分层：E2B/E4B 移动端，12B 统一多模态，26B-A4B 高容量低激活，31B dense 简化 serving。
- 显存估算至少为权重 + KV + activation + runtime workspace + encoder；不要只复制 Table 3。
- Serving 要明确 thinking 开关、最大 reasoning token 与 function-call template，否则 benchmark 配置不可复现。
- 若用 MTP speculative decoding，必须实际测 acceptance length、draft overhead 与 batch interference；有 drafter 不等于一定加速。
- 128k 能接收不等于能推理，应分别测 retrieval、multi-hop、GraphWalks 与业务长文；E2B 的 4.1 F1 正说明 size 仍是瓶颈。
- QAT checkpoint 要在目标 backend 上测 kernel 支持；理论位宽与实际 latency/内存取决于 llama.cpp、mobile runtime 或 accelerator。

## 思考题

<details class="thought-question"><summary>1. 为什么 26B-A4B 不能简单说成“只需 4B 模型的显存”？</summary><div class="thought-answer">每 token 只激活约 3.8B 参数，不代表未激活 experts 不需存储。报告 Table 3 的 Q4_0 权重是 16.2GB total / 2.8GB active；serving 通常要加载 entire 26B expert pool，active 口径更接近 FLOPs，不是总显存。</div></details>

<details class="thought-question"><summary>2. 12B encoder-free 为什么可能更省内存，却不一定更省训练计算？</summary><div class="thought-answer">部署少了独立 550M/305M encoder 与组件切换，但主 LLM 必须从 raw patches/chunks 学到感知表示，可能需要更多数据或主干计算。报告只给最终架构和结果，没有等质量训练 FLOPs ablation。</div></details>

<details class="thought-question"><summary>3. global layer 令 V=K 会失去什么表达能力？</summary><div class="thought-answer">标准 attention 的 key 用于匹配、value 用于传递内容，绑在一起减少一个独立线性投影与 cache，却限制“按一种表示寻址、读取另一种表示”的自由度。模型可在前后层补偿；是否有质量损失需要 ablation，报告未单列。</div></details>

<details class="thought-question"><summary>4. AIME 89.2 vs 20.8 为什么不能全归因于 Gemma 4 backbone？</summary><div class="thought-answer">Gemma 4 表默认 thinking，Gemma 3 27B 明确 non-thinking；两代还不同数据、post-training 与可能的推理长度。数字证明最终系统更强，不识别单一 backbone 或架构的因果贡献。</div></details>

<details class="thought-question"><summary>5. 128k RULER 很高，为什么还要看 GraphWalks？</summary><div class="thought-answer">RULER 更偏检索与合成任务，GraphWalks 要组合长距离结构信息。E2B 在 RULER 128k 为 70.4，却在 GraphWalks 只有 4.1，说明“找到 token”和“基于长上下文推理”是不同能力。</div></details>

<details class="thought-question"><summary>6. 怎样公平评估 MTP 的真实价值？</summary><div class="thought-answer">固定主模型、prompt、sampling、batch 和硬件，对比无 drafter；报告 proposal length、接受前缀分布、drafter/verify FLOPs、TTFT、TPOT、吞吐、显存与质量。还要测短回答和高并发，因为 drafter overhead 可能抵消收益。</div></details>
