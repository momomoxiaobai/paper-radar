> [!NOTE]
> 论文于 **2026 年 11 月 5 日**首次公开，已列为 NeurIPS 2026 论文。本文选择它，不是因为“回滚”本身新，而是因为它把回滚变成了一个可与 SC@32 公平比较、固定答案预算、可并行执行的解码器。

## 一句话结论

**Self-consistency 把每一个新增答案都当作一条必须从头生成的独立轨迹；StepBack 先采少量草稿，用 step-level NLL 跳升或 PRM score 下降定位首个疑似错误，再保留此前前缀、只重采该步及后缀。它在三种 3B/7B 模型、七个数学与多跳问答数据集上，平均准确率大致追平或略高于 SC@32，同时少生成约 19%–33% token；但它省的是生成冗余，不是自动获得了可靠 verifier。**

## 问题背景：SC 的浪费发生在哪里

给问题 $x$ 和模型 $p_\theta$，标准 self-consistency（SC）独立采样 $B$ 条完整 chain-of-thought：

$$
\tau^{(b)}\sim p_\theta(\cdot\mid x),\qquad b=1,\ldots,B,
$$

抽取并归一化每条轨迹的最终答案，再返回众数。若平均轨迹长度为 $L$，生成成本近似为 $O(BL)$。Adaptive Consistency、Early-Stopping SC 与 Difficulty-Adaptive SC 会回答“采几条”，却仍把每条候选视为一条从零开始的完整轨迹。

StepBack 问的是另一个维度：**一条失败轨迹往往不是从第一步就错。**题目解析、变量定义、检索到的事实可能都正确，错误只在中段第一次出现；从那以后，后续推导被污染。如果能找到首错位置，重写 suffix 比丢弃 prefix 更经济。

作者先做 oracle 诊断：用 LLM verifier 标注真实首错位置，再从该位置采样。在 GSM8K 上，$8\times4$ 的 draft-suffix 分配用 3,427 token 达到 91.89%，而 SC@32 用 9,506 token 达到 91.21%，节省 64.0%；MATH500 的 $16\times2$ 也以 12,615 对 18,335 token 达到 73.00% 对 72.80%。这不是最终方法成绩，却证明“正确前缀值得复用”有可测价值。

## 两阶段预算：草稿数量与每个草稿的分支数

把每条草稿写成步骤序列：

$$
\tau^{(j)}=\left(z_1^{(j)},\ldots,z_{T_j}^{(j)},z_{T_j+1}^{(j)}\right),
$$

其中 $z_{T_j+1}$ 是最终答案步骤。总候选答案预算被分解为

$$
B=n_d n_s,
$$

$n_d$ 是独立草稿数，$n_s$ 是每个草稿贡献的答案数。每条草稿自身先贡献一个答案；若回滚点为 $\hat e_j$，再从保留前缀 $z_{<\hat e_j}^{(j)}$ 条件采样 $n_s-1$ 条新后缀：

$$
\widetilde z_{\hat e_j:T_j+1}^{(j,m)}
\sim p_\theta\!\left(\cdot\mid x,z_{<\hat e_j}^{(j)}\right),
\qquad m=1,\ldots,n_s-1.
$$

最后仍对 $B$ 个归一化答案做多数投票。因此与 SC@32 的关键公平性是：两者都给投票器 32 个答案；差别只在答案的生成结构。它不是用更少的 vote 换更少的 token。

## 定位机制 1：NLL-SIGNAL

对第 $t$ 个 reasoning step 的 token 求平均负对数似然：

$$
u_t=-\frac{1}{|z_t|}\sum_{y_i\in z_t}
\log p_\theta(y_i\mid x,z_{<t},y_{<i}).
$$

然后取相邻步骤的不确定性增量：

$$
\Delta\mathrm{NLL}_t=u_t-u_{t-1}.
$$

若某一步的平均 NLL 突然升高，模型在这里比上一步更不确定。回滚点是第一个超过阈值的步骤：

$$
\hat e_{\mathrm{NLL}}=
\begin{cases}
\min\{t:\Delta\mathrm{NLL}_t\ge\delta_{\mathrm{NLL}}\}, & \text{若存在},\\
T+1, & \text{否则}.
\end{cases}
$$

NLL-SIGNAL 不需要另一个模型，token probability 又是生成时已有量，因此便宜。但“模型变得不自信”与“逻辑第一次出错”不是同一件事：一个自信错误不会触发，正确但困难的变形会触发。实验也显示它更常在靠后位置回滚，省 token 更多，却可能保留早期错误。

## 定位机制 2：PRM-SIGNAL

过程奖励模型 $R_\phi$ 给问题与部分推理前缀打分：

$$
r_t=R_\phi(x,z_{\le t}).
$$

论文把可靠性下降写作

$$
\Delta\mathrm{PRM}_t=r_{t-1}-r_t,
$$

并取

$$
\hat e_{\mathrm{PRM}}=
\begin{cases}
\min\{t:\Delta\mathrm{PRM}_t\ge\delta_{\mathrm{PRM}}\}, & \text{若存在},\\
T+1, & \text{否则}.
\end{cases}
$$

主实验用 Qwen2.5-Math-PRM-7B，阈值固定为 $\delta_{\mathrm{NLL}}=0.1$ 与 $\delta_{\mathrm{PRM}}=0.05$，没有按数据集单独调参。无错误信号时，不回滚整条推理，只重采最终答案步骤，以补齐 $n_s$ 个答案。

PRM 的优势是显式判断过程质量，代价是额外模型、显存和 scoring latency。论文报告 scoring 占 StepBack wall-clock 的比例，而不是把 PRM 参数驻留、模型加载或多租户吞吐折算成统一成本。线上评估不能只看 generated token。

## 完整算法

对每个 $j=1,\ldots,n_d$：

1. 独立采样草稿 $\tau^{(j)}$，把原答案放进 multiset $A$；
2. 由 $\operatorname{Loc}(x,\tau^{(j)})$ 得到 $\hat e_j$；
3. 固定 $z_{<\hat e_j}^{(j)}$，独立采 $n_s-1$ 个 suffix，并把答案加入 $A$；
4. 返回 $\operatorname{mode}(\operatorname{Normalize}(A))$。

不同草稿与不同 suffix 之间没有“上一轮改写成功后才开始下一轮”的依赖，因此可以并行。它与 Thought Rollback、self-backtracking 的主要工程差别，正是一次性给每条草稿确定 rollback point 和固定总答案数。

## 实验设置

- 数学：GSM8K、MATH500、AMC2023、AIME24、OlympiadBench。
- 多跳问答：HotpotQA 随机 500 条验证样本、2WikiMultiHopQA 随机 1,000 条；不是全验证集。
- 模型：Qwen2.5-3B-Instruct、Llama3.2-3B-Instruct、Qwen2.5-7B-Instruct。
- 主预算：$B=32$，默认 $(n_d,n_s)=(16,2)$；sampling temperature 0.7，top-$p=0.95$。
- 指标：答案准确率、相对 SC@32 的 token saving $\eta$、每题 expansion 数、相对 greedy CoT 每 1k token 的准确率增益。
- 硬件：每次运行 4 张 96GB RTX PRO 6000 Blackwell，CUDA 12.8、PyTorch 2.7、vLLM 0.9.2。

token saving 定义为

$$
\eta=100\left(1-\frac{\operatorname{Tok/Q}(\mathrm{StepBack})}
{\operatorname{Tok/Q}(\mathrm{SC@32})}\right),
$$

而效率增益为

$$
\mathrm{G/1kT}(m)=1000\cdot
\frac{\operatorname{Acc}(m)-\operatorname{Acc}(\mathrm{CoT})}
{\operatorname{Tok/Q}(m)}.
$$

后者把“比 greedy 多出的准确率”除以总 token，适合比较预算利用率，但不能替代实际延迟/吞吐与显存测量。

## 主要结果：平均追平，逐任务并不总赢

<figure><img src="/paper-radar/images/stepback/results.svg" alt="StepBack 相对 SC 的平均 token 节省、准确率变化和与自适应方法组合的结果" width="1600" height="900" loading="lazy"/><figcaption>图 2：依据论文 Tables 2–3 重绘。条形后的第二个数字是相对 SC@32 的准确率变化（百分点），不是相对百分比。</figcaption></figure>

在按 4,166 个问题加权的平均结果上：

- Llama-3B：NLL 节省 27.74% token、$\Delta$Acc $-0.17$；PRM 节省 18.66%、$+0.36$。
- Qwen-3B：NLL 节省 27.15%、$+0.12$；PRM 节省 21.07%、$+0.17$。
- Qwen-7B：NLL 节省 33.32%、$+0.55$；PRM 节省 22.80%、$+0.82$。

这些平均数支持“更省且平均不降”，却不能改写成“每个任务都更准”。PRM 在 21 个 model-dataset pair 中 14 胜、1 平、6 负；Llama-3B 的 AIME24 两种信号都比 SC 低 2.22 点，HotpotQA 上 PRM 低 2.00 点。Qwen-7B 的 AIME24 同样低 2.22 点。困难竞赛题可能需要换整条解题路线，保留 prefix 反而锁死了错误策略。

效果最稳定的是中后段错误占比高的 GSM8K、MATH500、AMC2023。Qwen-7B/GSM8K 的 PRM 版本节省 41.26% token并提高 0.45 点；MATH500 三模型的 PRM 版本都更准且节省 20.81%–28.53%。

## 与自适应 SC 的真实关系

AC、ESC、DSC 决定“消费多少个候选”，StepBack 决定“每个候选从哪里生成”，两个轴可以叠加。Qwen-3B 上：

- StepBack+DSC 在 GSM8K 用 1,815 token 达到 92.12%，SC@32 用 9,506 token 达到 91.21%，约 5.2 倍 token 差；
- StepBack+ESC 在 HotpotQA 用 6,567 token 达到 35.0%，ESC 用 7,061 token 达到 32.8%；
- MATH500 上三个叠加版本比对应自适应 baseline 低 0.2–0.8 点，但 token 少 22%–24%。

因此它更像一个 candidate generator，而不是新的 stopping policy。工程上可把 suffix pool 暴露给任意预算控制器。

## 基线是否公平

主比较在候选答案数、generator、sampling 参数与 benchmark 上基本对齐，优点明显。但仍有四个口径需要保留：

1. PRM-SIGNAL 使用 7B 外部模型，而 generator 有 3B；token 指标只统计生成 token，不等价于总 FLOPs。
2. 默认 StepBack 的 16 条草稿并非与 SC 的 32 条独立 reasoning prefix 同多样；准确率更高或更低都可能来自相关采样结构。
3. multi-hop 数据是抽样子集，且只有 exact match，没有检索证据质量或部分正确指标。
4. 论文对阈值做了 held-out grid 检查和五随机种子实验，这是加分项；但 21 个 pair 的单项差异仍不都带置信区间。

## 局限与风险

- 首错假设把 reasoning 看成线性步骤；如果错误来自最初表示、隐式检索或多个步骤的组合，单点回滚不够。
- blank-line step parser 依赖输出格式。生产模型可能混用段落、工具调用和结构化字段。
- suffix 共享同一 prefix，投票样本相关；多数票的有效样本量小于 $B$。
- PRM 主要受数学过程监督，在 HotpotQA 的跨域收益不稳定；错误定位也可能被奖励模型偏见系统性带偏。
- 论文未验证代码生成、长文摘要、tool-use trajectory 与闭源模型，不能直接外推到 Agent rollback。

## 工程启示

- 保存结构化 step boundary、token logprob 与 KV prefix，才能让 suffix retry 真正减少计算；只在文本层拼 prompt 可能重新 prefill 整个前缀。
- 线上应同时记 `draft_id`、rollback point、signal value、suffix token、answer cluster 与最终 vote，才能区分省在何处。
- 不要只设一个固定阈值。可按业务风险分层：低风险用 NLL，困难请求再启 PRM；同时监控被回滚位置分布是否漂移。
- 对 Agent 轨迹，先以编译失败、工具返回码、测试差异等可执行 signal 定位；PRM 应补充而非覆盖硬证据。
- 若草稿很少、suffix 很多，token 最省但 prefix diversity 低；论文显示 $2\times16$ 效率高，$8\times4$ 与 $16\times2$ 更稳。

## 思考题

<details class="thought-question"><summary>1. 为什么固定 B=32 仍不能说 StepBack 与 SC 的“统计预算完全相同”？</summary><div class="thought-answer">两者最终都有 32 个答案，但 SC 有 32 个独立 prefix，StepBack 只有 $n_d$ 个 prefix，同一草稿下的 suffix 条件相关。多数票的独立有效样本量不同；公平性成立在候选数与 generator 口径，不等于样本结构相同。</div></details>

<details class="thought-question"><summary>2. NLL 突升为什么可能是正确推理的信号？</summary><div class="thought-answer">困难但必要的代数变形、罕见事实或精确数值本来就低概率。NLL 衡量模型分布下的意外程度，不衡量逻辑真值。它适合低成本定位候选点，需要与执行器、PRM 或答案验证组合。</div></details>

<details class="thought-question"><summary>3. 如果 suffix 都更短，为什么准确率有时还能高于独立 SC？</summary><div class="thought-answer">因为错误草稿常包含正确问题设置；复用前缀避免重新抽到更差的开头，并把同样的生成预算集中在疑似错误附近。另一方面，这也是偏置：若 prefix 本身错，相关 suffix 会一起失败，所以困难题上可能反向。</div></details>

<details class="thought-question"><summary>4. 怎样把 StepBack 迁移到 coding agent？</summary><div class="thought-answer">把 step 定义为 observation–action–result 单元，优先用测试回归、编译错误、patch apply failure、权限拒绝等确定性 signal 找回滚点；从最近一个可恢复 checkpoint 重启，并保持相同总 attempt budget。还需区分环境副作用是否可逆，不能盲目复用旧状态。</div></details>

<details class="thought-question"><summary>5. 为什么“最多节省 41.26%”不应成为默认容量规划数字？</summary><div class="thought-answer">它来自 Qwen-7B/GSM8K/PRM 的特定 pair；加权平均更接近 19%–33%，且没有计入 PRM 常驻、KV 存储、调度和长尾延迟。容量规划应按自家长度分布、回滚位置和并发结构重测。</div></details>

<details class="thought-question"><summary>6. 若最终答案本身格式错，但推理正确，T+1 fallback 有什么价值？</summary><div class="thought-answer">它保留完整 reasoning，只重采 answer step，正好修复答案抽取、单位或格式层错误；也能补齐候选数。但若模型在同一 prefix 下确定性很强，多个 answer suffix 可能没有足够多样性。</div></details>
