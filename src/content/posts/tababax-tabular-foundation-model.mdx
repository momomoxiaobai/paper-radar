> [!NOTE]
> 技术报告于 **2026 年 10 月 31 日**公开。TabAbax 不是聊天模型，也不会生成表格文字；它接收同一张表中的已标注训练行和待预测行，在一次 forward 中输出分类概率或回归分布。本文会先解释这种 in-context learning 与普通表格训练的区别，再进入 Method 和实验。

## 阅读建议：如果你第一次接触表格基础模型

先记住三个概念就能读前半篇：

1. **一行**通常是一个样本，**一列**是一个 feature，label 是要预测的目标；
2. 传统方法会为每张表单独训练模型；TabAbax 在大量合成任务上预训练一次，测试新表时直接把已标注行当 context；
3. attention 让一个 query row 查看其他 context rows，但行数很多时两两比较的成本会平方增长。

如果 classification probability、regression、quantile 还不熟，建议先补：**监督学习 → train/test split → 分类与回归 → MAE/RMSE/交叉熵 → Transformer attention**。不理解 Muon optimizer 不影响读懂核心方法。

## 一句话结论

**TabAbax 沿用 TabICLv2 的“在合成表格任务上预训练、对新数据集做 in-context prediction”路线，只改动压缩前的上游：用 learned Fourier features 编码标量，执行两轮不共享参数的 column–row interaction，再通过循环三元特征组让不同列多次相遇；压缩成 row token 后仍使用 12 层 ICL Transformer 和 QASSMax 选择 query 相关的 context。它在 TabArena 回归上比 TabICLv2 高 336 Elo，其中仅升级合成任务 prior 就贡献 228，说明训练分布设计比单纯堆网络更关键。**

## 1. 为什么表格数据也需要“基础模型”

传统表格流程对每个数据集分别 fit：

$$
\theta_D^*=\arg\min_\theta
\sum_{(x_i,y_i)\in D_{\mathrm{train}}}
\mathcal L(f_\theta(x_i),y_i).
$$

XGBoost、CatBoost 或 MLP 都属于这一路。表格基础模型则在许多任务 $\mathcal T\sim p(\mathcal T)$ 上预训练参数 $\phi$，测试新数据集时不再做常规 gradient update，而是条件于 context：

$$
p_\phi\!\left(y_q\mid x_q,
\{(x_i,y_i)\}_{i=1}^{n}\right).
$$

这很像把训练集放进 prompt：已标注 rows 是 demonstration，query row 是问题。优势是小数据和快速推理；难点是表格没有自然固定 schema，不同任务的列数、尺度、类别和 target mechanism 都在变化。

## 2. TabPFN / TabICL 路线的关键：学习一个任务先验

模型不可能见过所有真实数据集，因此先从一个 synthetic prior 采样数据生成过程：随机选择 feature distribution、因果/计算图、非线性函数、噪声、类别比例和 target rule，形成大量“训练集 + query + 真值”任务。预训练可写成：

$$
\min_\phi
\mathbb E_{\mathcal T\sim p_{\mathrm{syn}}}
\mathbb E_{(D,x_q,y_q)\sim\mathcal T}
\left[-\log p_\phi(y_q\mid x_q,D)\right].
$$

因此 synthetic prior 不是普通 data augmentation；它定义模型认为什么样的表格世界更可能。若 prior 太简单，模型不会遇到真实 interaction；若过滤太强，又会误以为所有任务都具有清晰可预测信号。

## 3. Method 第一处改变：learned Fourier scalar encoding

表格里的一个数字 3.7 本身没有 token embedding。直接线性投影很难同时表达局部阈值、周期和多尺度变化。TabAbax 对每个标量构造 $K=16$ 个可学习 Fourier component。可将其直观写为一族：

$$
e_k(x)=
\left[
\sin(\omega_k x+\varphi_k),
\cos(\omega_k x+\varphi_k)
\right],
\qquad k=1,\ldots,16,
$$

其中频率/相位和后续投影通过训练学习。不同频率让模型更容易组合出“在某阈值附近改变”“对尺度敏感”或“局部起伏”的函数。这里的公式是 encoding intuition；实现细节应以代码为准，不能据此假设所有列具有周期物理意义。

类别值还要处理 declared category 数、实际出现类别和 one-hot 宽度一致性。报告特别修复了 synthetic generator 中三者可能不匹配的问题，因为错位会让模型学到生成器 artifact，而非类别结构。

## 4. Method 第二处改变：压缩前做两轮 column–row interaction

一行有 $m$ 个 feature，一张表有 $n$ 行。如果立刻把整行压成一个 token，列间细节可能过早丢失。TabAbax 在 compression 前做两轮 column–row pass，并且两轮参数不共享：

1. 在列/feature 维度建立同一行内部的关系；
2. 在行维度让同一特征的不同样本交互；
3. 再用另一组参数重复一次，让第二轮能基于第一轮形成的表示学习不同功能。

“untied”意味着：

$$
Z^{(2)}=B_{\theta_2}(B_{\theta_1}(Z^{(0)})),
\qquad \theta_1\neq\theta_2.
$$

若共享参数，则更像同一个迭代算子跑两次；不共享允许第一轮偏向规范化/局部关系，第二轮偏向组合，但也增加参数和过拟合空间。

## 5. 循环三元特征组：让有限窗口覆盖更多列组合

对第 $j$ 列，报告使用循环偏移构造特征组：

$$
G_j=(j,\;j+1,\;j+3)\pmod m.
$$

例如 $m=6$ 时，$G_0=(0,1,3)$，$G_4=(4,5,1)$。同一 feature 会在多个 group 与不同邻居相遇，避免只按固定连续 chunk 分组时，远距离列永远不交互。modulo 让最后几列绕回开头，不需要为任意列数另写边界逻辑。

这不是穷举所有 $O(m^2)$ feature pair，因此复杂度仍可控；代价是 interaction coverage 由预设 offsets 决定，某些高阶组合仍需后续层间接传播。

## 6. Target-aware embedding：训练行知道自己的标签

context row 不只是 feature vector $x_i$，还带 label $y_i$；query row 的 label 则未知。Target-aware embedding 把标签信息注入 context representation，让网络学习“feature pattern 与 target 的映射”，而不是只做无监督 row similarity。

设计上必须严格 mask query target，避免最直接的 label leakage。表格 benchmark 还要防止 preprocessing 在 train+test 全体上拟合、同一实体跨 split 或时间穿越；模型内部 mask 正确，不代表外部数据流程就没有泄漏。

## 7. Row compression、12 层 ICL backbone 与 QASSMax

完成上游 column–row interaction 后，每行被压缩成 row-level representation，再进入 12 层 $\mathrm{TF}_{\mathrm{icl}}$。对 query 来说，全部 $n$ 个 context row 并非同样有用；QASSMax 根据 query 自适应选取最相关的 context rows，再完成 ICL prediction。

这可以类比 retrieval：query 不必平均读取所有样本，而是把计算集中到邻近、代表性或决策边界相关的 rows。它也带来失败模式：若筛选相似度学错，少数群体或稀有模式可能在进入深层推理前就被丢掉。

报告给出的整体复杂度仍为：

$$
O(n^2+nm^2),
$$

分别对应行间关系和每行内 feature interaction 的主要成本。对十万级行数，这仍不是常数时间魔法；bounded context 和 QASSMax 是管理成本，而非消除缩放问题。

## 8. 分类与回归为什么分开训练

TabAbax 为 classification 和 regression 训练独立 checkpoint。分类预测类别分布；回归不只输出一个点，而是预测 999 个 quantile。对 quantile level $\tau\in(0,1)$，pinball loss 为：

$$
\mathcal L_\tau(y,\hat q_\tau)
=
\begin{cases}
\tau(y-\hat q_\tau), & y\ge \hat q_\tau,\\
(1-\tau)(\hat q_\tau-y), & y<\hat q_\tau.
\end{cases}
$$

当 $\tau=0.5$，它对应 median absolute error；多个 $\tau$ 共同描述条件分布，而不只给出 mean。999 个 quantile 提供很细的分辨率，但并不自动保证 calibrated interval，quantile crossing 和分布迁移仍需检查。

最终 checkpoint 规模并不巨大：classifier 28.85M 参数、231.15 MB；regressor 29.84M、239.03 MB。这里文件大小约为参数数的 8 倍，说明发布 artifact 不应简单按 FP32 的 4 bytes/parameter 猜存储格式，还要看 state 与 serialization。

## 9. 合成 prior 到底改了什么

相对 TabICLv2，TabAbax 的 generator 变化包括：

- 为计算图节点增加更多 function family 和 hyperparameter；
- 严格对齐 declared、emitted 与 one-hot categorical width；
- 更丰富地采样 class frequency，包括 Dirichlet draw；
- 回归取消事后 monotone target warping，减少“排序不变但尺度被人为改变”的捷径；
- 拒绝没有足够 signal / predictability 的 synthetic task。

最后一项是双刃剑。过滤坏任务能提升训练效率，防止网络在近乎随机标签上浪费容量；但现实表格经常 weak-signal、high-noise，若预训练总能看到可预测任务，部署时可能过度自信。

## 10. 三阶段课程与训练成本

classification / regression 分开训练，课程为：

| 阶段 | steps | 每任务行数范围 | 作用 |
|---|---:|---:|---|
| Stage 1 | 500K | 1,024 | 大规模学习 prior 和基本 ICL |
| Stage 2 | 40K | 400–10,240 | 适应变化 context length |
| Stage 3 | 10K | 400–60K | 延伸到长表格 |

训练最多 100 features、batch size 64，使用 Muon optimizer 和 8×H20 GPU。报告估计总计约 **2,700–3,500 GPU-hours**。后两个阶段 steps 少，却把 context 拉长很多，单 step 成本不能与 Stage 1 直接等同。

## 11. 关键实验：模型变好，究竟是谁的功劳

<figure><img src="/paper-radar/images/tababax/results.svg" alt="TabAbax 在 BeyondArena 和 TabArena 的 Elo 结果及合成先验消融" width="1600" height="900" loading="lazy"/><figcaption>图 2：根据技术报告主结果与 prior ablation 重绘。Elo 是跨数据集相对排序分，不是准确率百分点；不同 arena 的绝对 Elo 不应直接横比。</figcaption></figure>

主要结果：

| Benchmark | TabAbax Elo / 排名 | 相对 TabICLv2 |
|---|---:|---:|
| BeyondArena overall | 1,238 / 10 of 41 | +68 |
| TabArena overall | 1,676 / 11 of 99 | +115 |
| TabArena classification | 1,647 / 12 of 99 | +76 |
| TabArena regression | 2,024 / 7 of 99 | **+336** |

TabArena regression 还比 TabFM 高 21 Elo。要注意：Elo 把许多 dataset 上的 pairwise win/loss 汇总为相对 rating；+336 不是“误差下降 336%”，也不能在另一个参赛池直接解释成同样差距。

最有价值的是 prior-only ablation：只更换合成 prior、尚未加入全部 architecture 改动时，regression 已提升 **+228 Elo**，约为完整 +336 的三分之二；classification 只提升 **+12**，而完整为 +76。由此可得更精确的结论：

- 回归的主要跃升来自 synthetic task distribution；
- 分类更依赖 architecture、training recipe 或它们与 prior 的 interaction；
- 不能用“新编码器整体更强”一句话解释两类任务。

## 12. 与传统强基线怎样比较才诚实

表格模型没有在所有数据规模上统一胜者。Foundation model 的优势是少/中等样本、低调参成本和一次 forward；boosted trees 的优势是成熟、快、可按当前数据充分调参，且超大表格不受固定 context 同样限制。

公平比较至少要固定：

- preprocessing 和 train/validation/test split；
- tuning budget 与 wall-clock；
- 是否允许 ensemble；
- GPU/CPU inference 成本；
- 缺失值、类别编码和超高基数列的处理；
- 按 dataset 聚合，而不是让大数据集淹没小数据集。

Elo 很适合回答“跨许多 dataset 谁更常胜”，却不能替代单个业务数据集上的误差、校准、延迟和成本。

## 13. 局限与风险

1. **prior mismatch。** synthetic generator 决定模型归纳偏置，真实任务若超出 function/noise family，ICL 可能失效。
2. **predictability selection。** 拒绝弱信号任务可让 benchmark 更强，也可能让模型面对现实噪声时过度确信。
3. **context 有上限。** 60K 行训练不等于任意百万行可用；$O(n^2)$ 项仍制约扩展。
4. **context poisoning。** 错标签、重复实体、分布漂移和 adversarial row 会被当作 demonstration 条件。
5. **schema 语义弱。** 单靠数值与类别编码不一定理解列名、单位、因果方向和业务约束。
6. **benchmark contamination / tuning。** 模型和 prior 设计反复参考 public arena 时，隐藏 benchmark 与真实部署验证更重要。
7. **不确定性不自动校准。** 999 quantiles 很丰富，但 prediction interval 仍要按新域评估 coverage。

## 14. 工程启示

- 把 synthetic generator 当作一等模型组件：版本化 task family、噪声、class balance 和 reject rate。
- 做 prior ablation，而不是只比较最终 checkpoint；它能告诉你收益来自数据还是网络。
- 新数据集上线前，用 context corruption test：逐步注入错标签、删稀有类、改变 class ratio，观察性能与置信度。
- 与 CatBoost/LightGBM 做同预算 baseline；foundation model 可以作强默认值或 ensemble member，不必取代所有专用训练。
- 回归同时评估 point error、interval coverage、quantile crossing 和 tail behavior。
- 大表应把 QASSMax 当 retrieval subsystem 单独监控：选了哪些 rows、少数群体是否被系统性漏选。

## 思考题

<details class="thought-question"><summary>1. 为什么 synthetic prior 可以贡献比 architecture 更大的回归提升？</summary><div class="thought-answer">预训练目标是对 prior 中的任务做近似 Bayesian/algorithmic inference。若旧 prior 缺少真实的函数、噪声和 target mechanism，再强的网络也只会更好拟合错误世界；更接近真实任务的 prior 直接改变应学习的规律。+228 vs +336 的消融正支持这一点。</div></details>

<details class="thought-question"><summary>2. “测试时不训练”为什么仍叫 in-context learning？</summary><div class="thought-answer">模型参数不对新表做梯度更新，但 prediction 仍条件于已标注 context rows；改变 context 就会改变 query 输出。学习发生在 forward 的条件计算中，而不是 optimizer 更新中，因此也可理解为 amortized learning algorithm。</div></details>

<details class="thought-question"><summary>3. QASSMax 只保留最相关行，会产生什么系统性错误？</summary><div class="thought-answer">多数模式通常更容易被检索，稀有类、边界样本或分布外样本可能被早期丢弃；错标签的近邻也可能被放大。需要审计 selection recall、分群覆盖和对 corruption 的敏感性，而不只看最终平均分。</div></details>

<details class="thought-question"><summary>4. 999 个 quantile 是否一定比预测均值更好？</summary><div class="thought-answer">它表达的信息更多，能近似条件分布和非对称尾部，但增加输出/训练复杂度，并可能 quantile crossing。若业务只需平方误差下的点预测，可靠均值可能足够；若要风险区间，则 quantile 的校准价值更大。</div></details>

<details class="thought-question"><summary>5. 为什么不能把 +336 Elo 写成准确率提升 33.6%？</summary><div class="thought-answer">Elo 由模型在多数据集上的 pairwise 相对胜负推导，刻度取决于 rating system 和参赛池，不是一个有固定物理含义的百分比。应同时查看每数据集原始 metric、win rate 和统计不确定性。</div></details>

<details class="thought-question"><summary>6. 如果真实数据是百万行，应该怎样使用 TabAbax？</summary><div class="thought-answer">不能把全部行盲目放进 $O(n^2)$ context。可在无泄漏前提下做代表性/局部检索、分层抽样或 prototype selection，再与在全量数据训练的 boosted tree 比较；还要验证检索是否保留稀有群体和时间分布。</div></details>
